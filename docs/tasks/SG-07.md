# SG-07 — Catálogo pedagógico

**Status:** planejada · **Branch sugerida:** `feature/sg-07-catalogo-pedagogico` · **Área:** backend e banco de dados.

## Objetivo
Adicionar ao backend o catálogo hierárquico **Curso → Módulo → Unidade Curricular (UC)**, aproveitando ASP.NET Core 8, EF Core e os padrões existentes do SalaGest. Esta tarefa não inclui telas React nem carga horária detalhada.

## Escopo
- Examinar primeiro `Backend/Models/Domain.cs`, `Backend/Data/AppDbContext.cs`, `Backend/Contracts/Requests.cs`, `Backend/Endpoints/` e as migrations existentes.
- Criar entidades para **Curso**, **Módulo** e **UC**, com chaves e relacionamentos obrigatórios: curso com vários módulos; módulo pertencente a um curso; módulo com várias UCs; UC pertencente a um módulo.
- Dados mínimos: curso (código, nome, ativo/inativo), módulo (nome, ordem), UC (código, nome). Aproveitar padrões existentes para nomes, tamanho de campos e DTOs.
- Criar endpoints de inclusão, consulta e atualização, com listas de módulos por curso e UCs por módulo. Operações de escrita devem exigir o perfil administrativo atual; consultas autenticadas conforme política vigente.
- Validar campos obrigatórios, códigos/ordens duplicados dentro do contexto adequado, existência das entidades relacionadas e tratamento adequado de erros HTTP.
- Proteger registros referenciados contra exclusão acidental. **Não adicionar exclusão física nesta tarefa**, salvo necessidade já suportada por padrão do projeto.
- Fazer mudanças pequenas, usando o `AppDbContext` atual. Não criar repositórios genéricos, arquitetura de múltiplas camadas ou bibliotecas novas sem necessidade.

## Fora do escopo
- SG-08: carga horária, capacidades, competências e conteúdos.
- Vinculação de cursos/UCs a turmas, professores, aulas e reservas.
- Mudanças em reservas, empréstimos, autenticação, frontend ou dashboard.
- Reestruturação global de entidades existentes.

## Banco de dados e ambiente
- A migration `InitialCreate` já está no repositório. **Nunca recriá-la, sobrescrevê-la ou editar o snapshot manualmente.**
- Caso haja .NET e ferramentas EF disponíveis, gerar uma migration incremental apropriada, revisá-la e executar testes.
- Caso não haja .NET/SQL Server, não inventar migrations geradas. Deixar as alterações no modelo e descrever os comandos futuros para gerar/revisar/aplicar uma migration incremental em um banco de teste.

## Critérios de aceite
- [ ] Curso pode ser criado, listado, consultado e atualizado.
- [ ] Módulo pode ser vinculado a um curso existente e listado pelo curso.
- [ ] UC pode ser vinculada a um módulo existente e listada pelo módulo.
- [ ] Entradas inválidas, duplicidades e IDs inexistentes recebem respostas adequadas.
- [ ] Operações de escrita rejeitam usuários sem a permissão necessária.
- [ ] Exclusões em cascata indevidas não são introduzidas.
- [ ] Nenhum fluxo atual de reservas, empréstimos ou agenda é alterado intencionalmente.
- [ ] Testes executados são identificados; o que não pôde ser testado permanece marcado como pendente.
